Eastern default timezone, durable deliberate resets, USB charge-latch recovery, RTC binding guard

First release under the product-version scheme major × 100 + iteration: product version 4901 (v48 was 48). Built by GitHub Actions from the merge commit of the version-bump PR; the binary that ships is the binary that was soaked.

What changed since v48 (`v48-OccupancyEndsAtClose`)
- Item 25, default time zone (WO-2026-11-02-004, #176): `DEFAULT_TIMEZONE` is now the product 42131 default, `EST5EDT,M3.2.0/2:00:00,M11.1.0/2:00:00`, so a fresh device runs Eastern from first boot instead of UTC until a ledger zone is applied. A ledger time-zone change still takes effect at the next reboot. Confirmed on ChurchSt-2 over two days (boundary catch-up close stamped 02:59:59Z, last report 03:00Z, no 22:00Z close).
- Item 26, durable deliberate resets (WO-2026-11-03-005, #181): `flushAllBeforeReset()` force-flushes occupancy/daily totals/open session/alert codes, system status, sensor settings and then the publish queue before a deliberate reset or power-down, at seven sites (thrash tier 3, Error soft and hard, nightly heap guard, sleep exhausted, failsafe stages 2 and 3). Not flushed, by design: out of memory, the hardware watchdogs, the ApplicationWatchdog callback, HIBERNATE. Known limitation: at most one in-flight publish event can be lost per deliberate reset (fix is in the queue library, not touched here).
- Item 22, USB charge-latch recovery (WO-2026-11-02-001, #172): one charging cycle after 2 h stuck at Not Charging. [IN: pending #172 merge.] Known limitation: alert 22 may clear early after a real charge fault and can mask alert 20 (recorded in the alert reference).
- RTC binding guard (WO-2026-11-04-002): at boot, any stored Device OS RTC binding (`EXRTC_CONFIG_DATA`) is deleted, so a later build that binds the AB1805 natively can always roll back to this version. [Same-boot delete / delete-then-reset: per Stage 6.] No effect on a device without a stored binding (the whole fleet today).
- Release pipeline (workflow only, no firmware change): tag-triggered build, GitHub Release and Particle upload behind the Environment approval (#180, #183).

Not in this release: item 19 C1/C2 (untrusted-clock session merging; held for v50), the AB1805 native-driver switch (v50). v49 is the rollback floor once v50 ships.
