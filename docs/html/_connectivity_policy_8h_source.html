14 * SINGLE SOURCE OF TRUTH

21 * SAFETY / CHANGE CONTROL

23 * Hardware testing is ongoing; this header is documentation + naming only.
24 * DO NOT change any values without validating Particle modem behavior and field
25 * power impact.

37// ===== Connection attempt budgets =====
38// Purpose:
39// - Bound how long we will wait for a single connection attempt before declaring
40// failure and returning to low-power operation.
41// - Provide two budgets: a normal budget (IMSI cycling) and a periodic “deep”
42// budget that is long enough to allow a full modem reset path.
43//
44// Rationale / tradeoffs:
45// - Too short: modem may never reach the reset/registration behaviors needed for
46// recovery in marginal RF environments.
47// - Too long: repeated long attempts can burn the daily energy budget on solar.
48//
49// Invariants / safety notes (DANGEROUS to change):
50// - CONNECT_BUDGET_DEFAULT_MS MUST remain >= Particle cellular guidance for IMSI
51// cycling (~5 minutes). Reducing below this can permanently increase alert 31
52// rates in weak coverage.
53// - CONNECT_BUDGET_DEEP_MS MUST remain >= the window that allows the modem “full
54// reset” behavior (observed around the 10-minute mark). Reducing can eliminate
55// the only recovery path for some SIM/tower edge cases.
56//
57// Relationship notes:
58// - Connect budgets >> service gate and disconnect budgets. We accept waiting
59// longer to connect (when there is a chance), but we do NOT wait long to tear
60// down or to service stuck cloud operations.
61constexpr unsigned long CONNECT_BUDGET_DEFAULT_MS = 5UL * 60UL * 1000UL; // 5 minutes
62constexpr unsigned long CONNECT_BUDGET_DEEP_MS = 11UL * 60UL * 1000UL; // 11 minutes
63constexpr unsigned int CONNECT_BUDGET_DEFAULT_SEC = 300U; // 5 minutes
64constexpr uint16_t CONNECT_BUDGET_CONFIG_MIN_SEC = 120; // Particle docs minimum
65constexpr uint16_t CONNECT_BUDGET_CONFIG_MAX_SEC = 900;
66
67// Periodic deep attempts (full modem reset around 10 minute mark)
68// Purpose:
69// - Decide when we temporarily allow the longer deep budget.
70//
71// Rationale / tradeoffs:
72// - Deep attempts are more energy-expensive. The counter-based threshold prevents
73// doing them every time, while the SoC threshold opportunistically permits them
74// when battery is healthy.
75//
76// Safety notes:
77// - These thresholds are usually safer to tune than the connect budgets themselves,
78// but can still increase energy consumption and carrier-network load if too
79// aggressive.
80constexpr uint8_t DEEP_ATTEMPT_COUNTER_THRESHOLD = 3; // deep when attemptCounter >= 3
81constexpr float DEEP_ATTEMPT_SOC_THRESHOLD = 50.0f; // deep when SoC > 50%

83// ===== Firmware update (stay-connected) budget =====
84// Purpose:
85// - Upper-bound how long we remain in a firmware-update dwell state before
86// abandoning and returning to normal low-power behavior.
87//
88// Rationale / tradeoffs:
89// - Keeps OTA from monopolizing the power budget in poor connectivity.
90//
91// Safety notes:
92// - Generally “medium risk” to tune: making it longer increases energy burn;
93// making it shorter can cause updates to fail more often.
94constexpr unsigned long FIRMWARE_UPDATE_MAX_MS = 5UL * 60UL * 1000UL;
95
96// ===== Service gate (queue + ledgers + OTA + webhook) before disconnect =====
97// Purpose:
98// - Before tearing down the cloud session for sleep, give critical cloud-related
99// operations a brief chance to complete (publish queue drain, ledger sync, OTA
100// status, webhook response).
101//
102// Rationale / tradeoffs:
103// - Prevents sleeping while important work is still in flight.
104// - Timeout prevents a stuck publish/handshake from keeping the modem on.
105//
106// Invariants / safety notes:
107// - This gate MUST remain much smaller than connect budgets. If this grows too
108// large, we risk “connected but doing nothing” battery drain.
109// - This gate directly protects against “modem left on” failures caused by an
110// application-level wait that never completes.
111constexpr unsigned long CLOUD_OPS_GATE_TIMEOUT_MS = 30000UL;
112constexpr unsigned long CLOUD_OPS_STATUS_LOG_INTERVAL_MS = 5000UL;
113
114// ===== Teardown/disconnect budgets =====
115// Purpose:
116// - Bound how long we will wait for cloud disconnect and modem power-off to take
117// effect after requesting it.
118// - Provide conservative defaults that can be overridden by ledger configuration
119// within a safe min/max range.
120//
121// Rationale / tradeoffs:
122// - Too short: we may declare failure while Device OS is still making progress.
123// - Too long: we can sit awake burning energy while the radio remains on.
124//
125// Safety notes (DANGEROUS):
126// - DISCONNECT_BUDGET_MIN_SEC/MAX_SEC protect against accidental “infinite wait”
127// from misconfiguration. Keep these tight enough to avoid runaway battery drain.
128// - DISCONNECT_STANDBY_MAX_MS is a hard cap used when network standby is enabled;
129// it prevents spending meaningful connection budget on a perfect teardown.
130//
131// Relationship notes:
132// - Disconnect budgets should remain < any “awake ceiling” implied by your sleep
133// interval strategy; otherwise we can burn most of the cycle just powering down.
134constexpr uint16_t DISCONNECT_BUDGET_MIN_SEC = 5;
135constexpr uint16_t DISCONNECT_BUDGET_MAX_SEC = 120;
136constexpr uint16_t DISCONNECT_CLOUD_DEFAULT_SEC = 15;
137constexpr uint16_t DISCONNECT_MODEM_DEFAULT_SEC = 30;
138constexpr unsigned long DISCONNECT_STANDBY_MAX_MS = 5000UL;
