So there is no OTA Device OS rollback. v44 is a one-way OS move for the fleet unless a device is reflashed over USB.

**Correction, Q2 "standby latch":** `preserveStandbyAfterNormalReturn` (`State_Sleep.cpp:343/379/1433/1440`) is a per-sleep standby carry-over flag, not the standby latch in the recovery plan.
- **The latch** is `session.modemUnstable` / `modemStandbySuppressed` (`StateMachine.h:61–62`). It is set by `markModemUnstable()` when a teardown exceeds `MODEM_UNSTABLE_SLOW_TEARDOWN_MS` = 10 s (`State_Sleep.cpp:31`, `:103–127`), and cleared by `maybeClearModemUnstable()` (`:129–148`) or at the daily close (`State_Report.cpp:83–91`).
- **Why it matters:** the latch trips on **modem-off elapsed time**. Any 6.6.0 change to how long `Cellular.disconnect()` + `Cellular.off()` take on the non-standby path (`State_Sleep.cpp:785`, `:944`; with the cloud already down, INF: the new graceful cloud disconnect should be a no-op there) would show up as slow-teardown trips.
- **For the v44 soak,** watch `MODEM_HEALTH: unstable reason=slow_teardown`, `SLEEP: modem-off complete elapsed=` (verbose), and warm-to-cold steps in `connecttime`, alongside the report's alert-15 watch.
