## Analysis (Codex)

## 1. Who touches the chip today?

**Answer: Device OS 6.6.0 does not automatically own or communicate with an unconfigured carrier-board AM18x5 on Boron. It does so at boot only when a valid binding is already stored under `SystemCacheKey::EXRTC_CONFIG_DATA`.**

- **OBS:** Boron enables the optional external-RTC and AM18x5 code (`HAL_PLATFORM_EXTERNAL_RTC=1`, `OPTIONAL=1`, `AM18X5=1`), but that only compiles support; it does not provide a device binding (`device-os-6.6.0/hal/src/boron/hal_platform_config.h:103-105`).
- **OBS:** Boot calls `hal_rtc_init()`, which calls `hal_exrtc_init()` and then attempts an external-time read (`device-os-6.6.0/hal/src/nRF52840/rtc_hal.cpp:77-85`).
- **OBS:** `hal_exrtc_init()` first loads `SystemCacheKey::EXRTC_CONFIG_DATA`; only a successful load calls `Am18x5::bind()`. Otherwise it tries `hal_exrtc_default_binding()` and returns `NOT_FOUND` when that is null (`device-os-6.6.0/hal/shared/exrtc_hal.cpp:253-265`).
- **OBS:** The shared default binding is weak and returns `nullptr` (`device-os-6.6.0/hal/shared/exrtc_hal.cpp:437-439`). A tree-wide search finds one platform override: Tracker, whose non-optional on-board RTC supplies I2C, address and pins (`deviceOS/6.6.0/hal/src/tracker/exrtc_hal.cpp:25-65`). Boron has none.
- **OBS:** When bound, `Am18x5::begin()` initializes/resets I2C if necessary, reads the AM1805 ID, configures pins and writes configuration (`device-os-6.6.0/hal/shared/am18x5.cpp:481-526`). Without a binding, `hal_exrtc_get_time_internal()` returns `NOT_FOUND` without I2C (`device-os-6.6.0/hal/shared/exrtc_hal.cpp:405-410`).
- **OBS:** GCC currently initializes the vendored object itself with `ab1805.withFOUT(WKP).setup()` (`gcc-src/src/Generalized-Core-Counter.cpp:658`); its setup begins Wire, detects the chip and reads wake/time state (`gcc-AB1805_RK/src/AB1805_RK.cpp:23-42`). No GCC source use calls `hal_exrtc_bind()` or `Am18x5.enable()` (`gcc-uses-with-lines.txt:1-56`).
- **INF:** Therefore, assuming no pre-existing cache entry, Device OS is **not a second I2C owner today**; `AB1805_RK` is the only owner.
- **OBS:** The wiring `enable()` path calls `hal_exrtc_bind()` (`device-os-6.6.0/wiring/inc/spark_wiring_exrtc.h:586-602`), and that function stores `EXRTC_CONFIG_DATA` before binding (`device-os-6.6.0/hal/shared/exrtc_hal.cpp:267-279`). `disable()` unbinds and deletes it (`device-os-6.6.0/wiring/inc/spark_wiring_exrtc.h:477-479`; `device-os-6.6.0/hal/shared/exrtc_hal.cpp:298-304`).
- **UNKNOWN:** Source cannot establish whether a fielded unit was previously flashed with some test/application that stored this key. It is possible in principle; current GCC does not create it.
- **INF:** A migration build will create the stored binding. Downgrading that device to old GCC without first deleting the binding would make Device OS bind at boot and then let `AB1805_RK` bind again—an explicit two-owner rollback hazard.
- **OBS:** The watchdog registry merely exposes `Am18x5Watchdog` as instance 2; I2C operations occur only through API calls, and its `init()` first requires `Am18x5::isPresent()` (`device-os-6.6.0/hal/shared/watchdog_hal.cpp:49-64,66-99`; `device-os-6.6.0/hal/shared/am18x5.h:377-427`). GCC’s existing `Watchdog` setup uses the default internal watchdog (`gcc-src/src/Generalized-Core-Counter.cpp:416-447`), not the external instance.
- **OBS:** Sleep only reaches the AM18x5 for an explicit RTC hibernate wake or `POWER_OFF`: RTC hibernate calls `hal_rtc_set_alarm()` (`device-os-6.6.0/hal/src/nRF52840/sleep_hal.cpp:1346-1365`), while `POWER_OFF` issues `HAL_EXRTC_COMMAND_SLEEP` (`device-os-6.6.0/hal/src/nRF52840/sleep_hal.cpp:1308-1343`). Optional-RTC validation rejects an unready device (`device-os-6.6.0/hal/src/nRF52840/sleep_hal.cpp:754-775`). There is no unbound background sleep transaction.

## 2. Required Boron configuration

- **OBS:** Use `particle::Am18x5Configuration`: `.i2c(Wire)` selects Wire and fixed address `0x69`; `.interruptPin(WAKEUP_PIN)` sets FOUT/nIRQ; `.watchdogPin(D5)` assigns the WDI/DONE GPIO (`device-os-6.6.0/wiring/inc/spark_wiring_exrtc.h:165-182,330-350`; `device-os-6.6.0/hal/inc/exrtc_hal_am18x5.h:47`).
- **OBS:** On the Boron carrier, I2C is D0/D1, wake is D8/WKP, and DONE is D5 (`gcc-src/src/device_pinout.h:35-43`); GCC’s logical wake pin is `WKP` (`gcc-src/src/device_pinout.cpp:42-45`). There is currently no logical constant for D5.
- **INF:** Configure `.defaultTimeSource(true)`, `.clockSource(RtcClockSource::EXTERNAL)`, and enable `AUTO_CLOCK_SOURCE_INTERNAL_ON_FAIL`; the first is the configuration default, while the capability maps to `rc_fallback` (`device-os-6.6.0/wiring/inc/spark_wiring_exrtc.h:135-137,223-255`; `device-os-6.6.0/hal/shared/am18x5.cpp:220-235`). Timed power-off refuses crystal-only operation without fallback (`device-os-6.6.0/hal/shared/am18x5.cpp:991-1005`).
- **OBS:** Call `Am18x5.enable(config)` and check its result; this binds and persists the configuration (`device-os-6.6.0/wiring/inc/spark_wiring_exrtc.h:586-602`; `device-os-6.6.0/hal/shared/exrtc_hal.cpp:267-279`). On later boots Device OS binds before application setup.
- **INF:** AOS/RC-on-battery should remain off unless Chip explicitly chooses it; GCC currently only observes AOS/FOS rather than configuring them (`gcc-src/src/Generalized-Core-Counter.cpp:675-682`).

## 4. Known defects

- **OBS:** The vendored three patched masks are XTCAL `0xc0`, LKO2 `0x20`, OMODE `0x10`; its comment records the former conflicting values (`gcc-AB1805_RK/src/AB1805_RK.h:874-896`). Device OS uses the same correct masks (`device-os-6.6.0/hal/shared/am18x5_defines.h:140-148`).
- **OBS:** The vendored `usingRCOscillator()` now reads OMODE with the corrected `0x10` mask (`gcc-AB1805_RK/src/AB1805_RK.cpp:113-123`; `gcc-AB1805_RK/src/AB1805_RK.h:887-895`). Device OS also tests OMODE, not ACF (`device-os-6.6.0/hal/shared/am18x5.cpp:620-627`).
- **OBS:** The suspected PWGT omission is real: `deepPowerDown()` performs a read-modify-write of OSC_CONTROL/PWGT without first writing CONFIG_KEY (`gcc-AB1805_RK/src/AB1805_RK.cpp:552-569,791-806`). `resetConfig()` likewise writes OSC_CONTROL and protected analog/output registers with no key (`gcc-AB1805_RK/src/AB1805_RK.cpp:125-165`).
- **INF:** The source proves the missing authorization sequence, but not the chip’s physical response. Device OS explicitly writes `CONFIG_KEY_OSC_CONTROL` (`0xa1`) immediately before PWGT (`device-os-6.6.0/hal/shared/am18x5.cpp:1046-1052`; `device-os-6.6.0/hal/shared/am18x5_defines.h:178-181`).
- **OBS:** Built-in `POWER_OFF` writes primary key/BATMODE, primary key/OUTPUT_CTRL, sleep wake polarity/masks, OUT2S=6, PWR2, oscillator key/PWGT, disables/restores WDT, installs the timed alarm, reads STATUS, enables interrupts, sets SLP, and verifies/polls SLP (`device-os-6.6.0/hal/shared/am18x5.cpp:1008-1055,1058-1137`).
- **INF:** The #151 bench must observe the power rail/modem, reset reason and elapsed off-time—not merely the stage-3 log. Vendored failure reaches its 30-second fallback `System.reset()` (`gcc-AB1805_RK/src/AB1805_RK.cpp:575-590`); native failure returns `ABORTED` instead of silently claiming success (`device-os-6.6.0/hal/shared/am18x5.cpp:1121-1137`). Stage 2 proves the ladder; stage 3 proves actual power removal and timed restart.

## 5. GCC logic that remains GCC’s

- **OBS:** Current GCC does not clear OF; it snapshots oscillator registers (`gcc-src/src/Generalized-Core-Counter.cpp:660-682`). Device OS clears OF when oscillator-event monitoring is configured and reports subsequent failures as events (`device-os-6.6.0/hal/shared/am18x5.cpp:630-652,695-714`). **Decision:** item 21 needs either “fault observed since bind” semantics or an API exposing the boot-sticky flag.
- **OBS:** Clock-trust policy stays app-owned; only its correction measurement and RTC write call the vendored driver (`gcc-src/src/time/Clock.cpp:374-419,477-479`). Substitute checked external HAL get/set calls.
- **OBS:** `HibernateCycle` retains its retained-state and timing verdict, but its RTC read maps to external HAL and its cached `WakeReason` has no native equivalent (`gcc-src/src/time/HibernateCycle.cpp:29-44,47-123`).
