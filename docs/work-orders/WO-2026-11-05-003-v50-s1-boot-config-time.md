## Plain goal
Let Device OS 6.6.0 own the carrier-board AB1805 for **boot, binding and time**: one fleet-wide configuration bound once with `Am18x5.enable()`, system time seeded by Device OS before `setup()`, and every application read or write of the external RTC going through `hal_rtc_*` with the external source. The vendored `AB1805_RK` object stays in the tree for S2 (alarm, watchdog, wake classification) and S3 (power-off) and is **not started** by S1. The clock-trust rule is unchanged. Motive: one owner of the chip (not a known defect: the vendored code works on Dev-14).

## Rulings that bind this piece
Configuration: `particle::Am18x5Configuration` with `Wire` (0x69), `.interruptPin(WKP)`, `.watchdogPin(D5)`, RC fallback on (`RtcCap::AUTO_CLOCK_SOURCE_INTERNAL_ON_FAIL`), always-on RC off. **The setter is `hal_rtc_set_time(HAL_RTC_SOURCE_EXTERNAL)`**, confirmed in Step 0 with a test, **or stop and name the alternative** (architect, 5 Nov). Reads: `hal_rtc_get_time(HAL_RTC_SOURCE_EXTERNAL)`; validity: `TimeClass(TimeSource::EXTERNAL).isValid()`. Clock trust unchanged until item 21.

## Amendment 3 (architect rulings on the Stage 6 findings, 6 Nov 2026)
1. **WRTC: verify every external write by reading it back.** After `hal_rtc_set_time(EXTERNAL)`, read back with `hal_rtc_get_time(EXTERNAL)`; **a mismatch of more than 2 s (or a failed read-back) counts as a failed write**, so the write-back's "confirmed success only" holds even if Device OS never sets the AM18x5 write-enable bit and the set silently no-ops. About +3 `src/` lines; **S1 stays within +20** (Stage 6 was net +16). This is an **architect-directed change** folded into the Stage 7 round (round 2 reviews it), not a restart. Tests: set then read back equal; mismatch over 2 s fails; exactly 2 s passes; a read-back error fails; mutations (no read-back; threshold removed; read-back error ignored) must fail.
2. **First boot from v49 (unbound device): the exposure is accepted; no seed-before-bind** (it would briefly create two owners of the chip). Device OS copies the internal time into the chip when it binds, so the chip time is not valid at that boot until the first cloud sync (about 20 s after an OTA boot). The clock is **untrusted until the first sync**, covered by C2 and the trust rules; a year-2000 chip time also fails I21's plausibility check. **Bench step 1 is changed:** on an unbound device the RTC becomes valid **after the first sync on that boot**, not at boot before the cloud (a bound device is valid at boot).
3. **Schema 3 covers both ledgers** (the constant is shared by the status and the data ledger); **Chip informs fleet-ops** of the `oscStatus`/`oscCtrl` nulls and schema 3 (their consumers are not in this repo).
4. **The oscillator latch goes to S4 (at most +10 `src/`),** as pre-ruled (Amendment 2). S4 is not drafted yet.
