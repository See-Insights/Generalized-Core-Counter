## 1. What GCC sets up

- **OBS:** GCC has no direct `setChargeVoltage`, `setChargeCurrent`, or `setInputCurrentLimit` call. It builds `SystemPowerConfiguration`: USB = 900 mA input, 3880 mV input minimum, 896 mA charge, 4112 mV termination; solar = 900 mA, 5080 mV, 900 mA, 4208 mV (`src/power/PowerPlatform.cpp:30-39,72-91`).
- **OBS:** On every boot, setup calls `PowerManager::setup()` immediately before the first battery/thermal sample (`src/Generalized-Core-Counter.cpp:1051-1085`). The profile is written only when no profile is yet valid or the selected profile changes (`src/power/PowerManager.cpp:184-204`).
- **OBS:** Profile selection maps USB host/adapter/OTG to USB and VIN to solar; battery/unknown retains the previous profile or uses the configured fallback (`src/power/PowerManager.cpp:21-49`).
- **OBS:** Every battery sample again rebuilds the complete profile and applies/clears `DISABLE_CHARGING`, with one retry and readback (`src/sensors/SensorManager.cpp:698-719,1177-1207`; `src/power/ChargeInhibit.cpp:7-36`). Samples occur at boot, reporting, connection, scheduled idle, pre-sleep and post-wake (`src/Generalized-Core-Counter.cpp:1084`; `src/state/State_Report.cpp:67-68`; `src/state/State_Connect.cpp:521`; `src/state/State_Idle.cpp:157-160`; `src/state/State_Sleep.cpp:356-361,1007,1025-1027`).
- **OBS:** Each Boron battery sample constructs a locked `PMIC`, reads REG09 twice and REG08 once, then runs remediation (`src/sensors/SensorManager.cpp:713-725`; `src/power/PmicFaultMonitor.cpp:82-98`). Diagnostic PMIC use is read-only (`src/power/PowerDiagnostics.cpp:193-205`; `src/power/PowerPlatform.cpp:41-69`).
- **OBS:** Triggered charger writes are: immediate USB fault toggle; level 1 after two faulty polls; level 2 after three; thermal inhibit enable/clear on every sample (`src/power/PmicFaultMonitor.cpp:122-175,290-306`; `src/power/ChargeInhibit.cpp:14-35`).
- **OBS:** `System.enableFeature` only enables reset information at startup; it is not charger configuration (`src/cloud/Particle_Functions.cpp:7-11`). No GCC `PowerManagement` object/call was found.

## 2. What an MCU reset re-applies

- **OBS:** `System.reset()` reaches an nRF `NVIC_SystemReset()`; that path contains no BQ24195 register reset (`deviceOS/6.6.0/wiring/src/spark_wiring_system.cpp:52-55`; `hal/src/nRF52840/core_hal.c:537-556`). Therefore an MCU reset is not itself a PMIC POR.
- **OBS:** Device OS boot loads the persisted power configuration, starts the PMIC, runs `initDefault()`, then reads REG09 twice to clear old latched state (`system/src/system_power_manager.cpp:211-270,1064-1119`).
- **OBS:** `initDefault()` re-applies watchdog policy, charge voltage/current, 100 mV recharge threshold, 256 mA termination current, charge-enable policy, BATFET, buck and input/DPDM configuration (`system/src/system_power_manager.cpp:547-620`).
- **OBS:** Boron does not override the common `HAL_PLATFORM_POWER_MANAGEMENT_PMIC_WATCHDOG=0`; consequently normal Device OS boot disables the PMIC watchdog (`hal/inc/hal_platform.h:452-454`; `system/src/system_power_manager.cpp:551-559`). The BQ24195 POR default is nevertheless REG05 `WATCHDOG[1:0]=01`, 40 s (PDF p.30, **8.5.1.6 Charge Termination/Timer Control Register REG05**).
- **OBS:** Watchdog expiry resets charger registers to defaults and returns it to default mode; any I²C write enters host mode, which must reset or disable the watchdog (PDF p.25, **8.4.1 Host Mode and Default Mode**). GCC level 2 explicitly selects the 40 s watchdog before enabling charging (`src/power/PmicFaultMonitor.cpp:65-79`).
- **OBS:** Boot does **not guarantee a new charge cycle or safety-timer restart**. Device OS toggles `CHG_CONFIG` and enables `EN_TIMER` only if `isChargingEnabled()` is false; if already enabled, it does neither (`system/src/system_power_manager.cpp:335-359`). A `00→01` `CHG_CONFIG` transition or `EN_TIMER 0→1` restarts the timer (PDF p.20, **8.3.3.5 Charging Safety Timer**).
- **OBS:** REG08 is live, read-only status; REG09 retains the prior fault until read, and two consecutive reads give previous then current state (PDF p.21, **8.3.4.2 Interrupt to Host**; PDF p.25, **8.4 Device Functional Modes**). GCC ORs both reads (`src/power/PmicFaultMonitor.cpp:82-98`); Device OS boot first consumes two reads (`system/src/system_power_manager.cpp:264-270`).
- **INF:** LAB-01 may have recovered because boot re-applied configuration or because a still-live REG09 charge fault caused GCC’s immediate toggle. Since Device OS consumes REG09 before GCC and no pre-reset register snapshot exists, the exact mechanism is UNKNOWN.
- **OBS:** Before sleep, Device OS disables the PMIC watchdog; wake without reset runs `initDefault()` again (`system/src/system_power_manager.cpp:295-319,496-521`). GCC hibernate is expected to reset the MCU (`src/state/State_Sleep.cpp:689-739`), after which the normal boot path runs.
- **OBS:** A true charger power cycle—VBUS and BAT falling below its supply threshold and subsequently rising—causes BQ24195 POR and resets all registers (PDF p.12, **8.3.1.1 Power-On-Reset**). Defaults enable charging through REG01 `CHG_CONFIG[1:0]=01` (PDF p.28, **8.5.1.2 Power-On Configuration Register REG01**).
- **INF:** That PMIC POR is the material difference from an MCU reset. Whether Trail02’s switch actually removed both BQ24195 supplies is UNKNOWN; field evidence only establishes that its manual power cycle cleared the blinking state (`docs/RECOVERY_PLAN_2026-09-26.md:294-322`).

## 3. Safety timer and fault states

- **OBS:** REG09 `CHRG_FAULT[1:0]`: `01` input fault, `10` thermal shutdown, `11` charge-safety-timer expiration; `BAT_FAULT` is bit 3 and `NTC_FAULT` bits 2:0 (PDF p.32, **8.5.1.10 Fault Register REG09**).
- **OBS:** GCC interprets those as codes `0x01`, `0x02`, `0x03`; alerts are respectively conditional 21, 20, and 21, with unclassified faults using 23 (`src/power/PmicFaultMonitor.cpp:192-224,382-388`).
- **OBS:** REG08 `CHRG_STAT[1:0]` is 00 Not Charging, 01 Pre-charge, 10 Fast Charging, 11 Termination Done (PDF p.32, **8.5.1.9 System Status Register REG08**). GCC maps a charge/battery fault to `BatteryState=5`/“Fault”; otherwise 00 maps to `BatteryState=1`/“Not Charging” (`src/sensors/SensorManager.cpp:3-5,148-162`).
- **OBS:** Safety expiry sets REG09 `CHRG_FAULT=11`; restarting requires a new cycle, CE toggle, REG01 `CHG_CONFIG 00→01`, or REG05 `EN_TIMER 0→1` (PDF p.20, **8.3.3.5 Charging Safety Timer**). A new cycle requires “no safety timer fault” (PDF p.17, **8.3.3.1 Autonomous Charging Cycle**).
- **OBS:** Therefore a drained USB unit whose safety timer expires can remain charge-suspended/Not Charging until one of those restart actions; its STAT indication is a 1 Hz fault blink (PDF p.20, **8.3.4.1 Charging Status Indicator**).
- **OBS:** Reading REG09 clears its historical latch but not an underlying live condition; the second read supplies current state (PDF p.25, **8.4 Device Functional Modes**).
- **INF:** Input and thermal faults clear when their physical conditions disappear; the datasheet establishes input OVP stopping and thermal shutdown, but does not give a universal host “clear” command (PDF p.21, **8.3.5.2 Thermal Regulation and Thermal Shutdown**; PDF p.22, **8.3.5.3.1 Input Over-Voltage**). Exact recovery from any other input-fault cause is UNKNOWN.

## 4. Thermal charge inhibit

- **OBS:** Compiled defaults arm outside 0–37°C and release inside 3–35°C; an already armed inhibit is held when no fresh temperature exists, while an uninhibited device cannot arm from stale temperature (`src/power/ChargeInhibitPolicy.h:23-28,107-118,143-177`).
- **OBS:** Thresholds are ledger-configurable and are sampled for every coupled decision (`src/power/ChargeInhibitPolicy.h:12-18`; `src/sensors/SensorManager.cpp:1097-1110`).
- **OBS:** An inhibit writes `DISABLE_CHARGING`; release clears it. The code explicitly records “Not Charging” and logs arm/release (`src/power/ChargeInhibit.cpp:14-35`; `src/sensors/SensorManager.cpp:1182-1199`).
- **OBS:** LAB-01’s 24–26°C lies safely inside the default band, so default policy could not arm. **UNKNOWN:** the supplied evidence does not include LAB-01’s resolved ledger overrides; an abnormal override cannot be excluded solely from source.

## 5. `PmicFaultMonitor` and non-fault Not Charging

- **OBS:** Immediate reset requires a charge-fault bit, safe temperature, REG08 power-good, USB VBUS/context, no thermal regulation/severe battery state, and a non-thermal fault (`src/power/PmicFaultMonitor.cpp:122-145`).
- **OBS:** Fault polls increment a counter; level 1 begins at two, level 2 at three, with a one-hour cooldown (`src/power/PmicFaultMonitor.cpp:104-115,194-196,277-313`).
- **OBS:** The monitor has no recovery branch for fault-free `CHRG_STAT=00`; that path merely clears/completes fault remediation (`src/power/PmicFaultMonitor.cpp:315-380`). Its separate six-hour detector covers only prolonged Fast Charging (`src/power/PmicFaultMonitor.cpp:483-530`).
- **OBS:** PMIC anomaly forensics only counts a safe-to-charge Not Charging/Charged contradiction below 20% SoC, after three polls (`src/sensors/SensorManager.cpp:754-780`). LAB-01 at 36% therefore naturally had `pmicAnomalyCount=0`; that counter does not exonerate the charger.

## 6. Candidate check and line cost

- **INF:** Run after the existing REG08/REG09 snapshot in `SensorManager::batteryState()`, where `safeToCharge`, VBUS, power-good, charge status, fault, vcell and source/profile are already sampled (`src/sensors/SensorManager.cpp:698-735`).
- **INF:** Predicate: USB host/adapter-backed input; `PG_STAT=1`; `CHRG_STAT=00`; no REG09 charge/battery fault; `safeToCharge`; usable vcell; and `BatteryHealth::restingSocFromVcell(vcell)<80%` (approximately vcell <4.05 V). This passes LAB-01’s 3.71–3.75 V but excludes normal termination and an ordinarily full USB cell (`src/power/BatteryHealth.cpp:24-31,52-74`).
- **INF:** Choose **N=2 h**: shorter than the observed 3.5 h outage but long enough to ignore ordinary state transitions. Use a plain boot-scoped `static` timestamp plus cooldown; no `retained` field and no persisted-layout change. A reset discards the timer, but the reset itself already performs the recovery path.
- **INF:** On expiry, raise alert 21, quick-start the gauge while status is still OFF, then request the existing level-1 nonblocking charge cycle. Do not use `PMIC::reset()`: REG01 `Register Reset` resets all charger settings and would create a larger configuration/reconciliation problem (PDF p.28, **8.5.1.2 Power-On Configuration Register REG01**).
- **INF:** Net `src/` estimate: predicate 5 + RAM timestamp/cooldown 2 + timing/reset logic 5 + request existing soft-cycle/alert 3 = **15 charger lines**; checked `quickStart()` call/log = **3 lines**; total **+18**, leaving 2 lines under the +20 budget. This fits only if the existing phase machine is reused; a second standalone phase machine does not fit.
- **INF false positives:** a full/aged cell sagging below 4.05 V; an intermittent or weak supply that is power-good at the poll; USB100/HIZ behavior; or load-induced voltage depression. Hot/cold enclosure and clear full-voltage cases are excluded. REG08 DPM bit is already available in `systemStatus` and should be a weak-supply exclusion (`src/power/PmicFaultMonitor.cpp:92-97`).

## 7. Test shape

- **INF host test:** feed a pure policy seam repeated USB+PG+OFF+no-fault+3.75 V samples; assert no action before 2 h, one action/alert at 2 h, cooldown thereafter, and timer reset on PRE/FAST/DONE, ≥4.05 V, fault, unsafe temperature, no PG, VIN/OTG, or DPM.
- **INF bench:** use a 30–60% battery and current-limited USB, with a bench-only elapsed-time injection. Force the sampled OFF predicate, confirm exactly one quick-start and charge cycle, then verify REG08 becomes PRE/FAST, REG09 remains clear, current rises normally, and no repeat occurs. Do not deliberately overcharge, heat/cool, short, or wait for a real safety-timer expiry.

## 8. Fuel-gauge re-estimate

- **OBS:** Boron declares a MAX17043 fuel gauge (`deviceOS/6.6.0/hal/src/boron/hal_platform_config.h:20-29`). GCC already owns a `FuelGauge` and reads its raw SoC/vcell (`src/sensors/SensorManager.cpp:31,501-515`).
- **OBS:** `FuelGauge::quickStart()` writes `0x4000` to the MAX17043 MODE register (`deviceOS/6.6.0/wiring/src/spark_wiring_fuel.cpp:247-255`). Device OS itself invokes it when transitioning from battery-disconnected to another state (`system/src/system_power_manager.cpp:659-666`).
- **UNKNOWN:** Without the MAX17043 datasheet, Device OS source does not establish quick-start conversion timing, accuracy, or electrical safety during charging.
- **INF:** A voltage-based re-estimate made at charging terminal voltage would read high: GCC’s reference curve gives 93% at 4.13 V, 98% at 4.18 V and clamps to 100% at 4.20 V (`src/power/BatteryHealth.cpp:29-31,52-74`). It is not a valid resting-SoC estimate.
- **OBS/INF:** The charging allowance only widens the negative-residual Untrusted threshold from 20 to 28 points (`src/power/BatteryHealth.cpp:35-44,94-102`). It catches a stale 40% gauge against 93%, but cannot catch a newly quick-started gauge that agrees with the same charge-inflated voltage. Thus it does **not** make quick-start-while-charging safe.
- **INF:** Cost is the 3 lines included above. Invoke quick-start only after the predicate has observed `CHRG_STAT=00` for N hours and before re-enable; never during PRE/FAST. Bench validation and the MAX17043 datasheet remain required.

## 9. Item 23 arithmetic and raw-SoC consumers

- **OBS:** At 4.13 V, interpolation between 4.10 V/90% and 4.20 V/100% gives **93%** (`src/power/BatteryHealth.cpp:30-31,64-74`). Residual = 40.46 − 93 = **−52.54 points**.
- **OBS:** While charging, negative Untrusted threshold = 20 + 8 = **28 points**; −52.54 is Untrusted (`src/power/BatteryHealth.cpp:35-44,94-102`).
- **OBS:** `socForTier()` substitutes the 93% voltage estimate whenever trust is not Trusted, and `BatteryAuthority` sends that value through tier hysteresis (`src/reporting/BatteryTierGuard.cpp:5-10`; `src/power/BatteryAuthority.cpp:17-38`).
- **OBS:** At 3.71–3.75 V, interpolation gives **31–35%**; against 36.14%, residual is +5.14 to +1.14, inside the ±12-point Suspect boundary and therefore Trusted (`src/power/BatteryHealth.cpp:24-25,39-44,64-74,99-105`).
- **OBS:** Raw gauge SoC is selected as authoritative and stored without correction (`src/sensors/SensorManager.cpp:501-515,740-752`). The reported webhook `battery` is raw (`src/cloud/ReportPublisher.cpp:76-106`), as are status `battery.soc` fields (`src/cloud/DeviceStatusPublisher.cpp:245-259,522-524`).
- **OBS:** Operational consumers outside `BatteryAuthority` are the connection deep-attempt budget (`src/state/State_Connect.cpp:115-134`) and PMIC trend/stuck-fast alert logic (`src/power/PmicFaultMonitor.cpp:420-443,483-520`). Logs/cycle diagnostics also retain raw SoC (`src/state/State_Idle.cpp:157-160`; `src/state/State_Sleep.cpp:356-370`; `src/power/PowerDiagnostics.cpp:187-203`).
- **OBS:** Reporting cadence and failsafe tier decisions are guarded: `evaluateCurrent()` gathers vcell/trust before evaluation (`src/power/BatteryAuthorityCommand.cpp:45-50`), and the failsafe cadence goes through the reporting-policy resolver (`src/power/ConnectivityFailsafe.cpp:264-274`).
