## Q10 — NAP/NIGHT versus phase modules

**Observation:** NAP/NIGHT would remove openness branches from the scripts at `State_Sleep.cpp:228–230,263–267,858–904,919–945`; the selector would still perform that decision. Post-wake openness checks at `:1467` and `:1641` must remain because time can cross the boundary during sleep.

Every transition into Sleep is: `ThrashGuard.cpp:144`; `State_Connect.cpp:601,654,711,729`; `State_Idle.cpp:138,267,344`; and the self-transitions `State_Sleep.cpp:1628,1664`. “park closed” maps directly to NIGHT; all other callers require a selector preserving Closed→NIGHT and Open/Unknown→NAP; both self-transitions must reselect after wake.

Every transition out is: Idle `State_Sleep.cpp:266,953,1668`; Firmware Update `:344`; Report `:355,863,1461,1519,1597,1632,1647,1654`; Error `:702,822,1369`; Connect `:1499`; and the two reselected sleep transitions `:1628,1664`. Their non-sleep destinations and reasons remain unchanged.

A literal split also requires both states in ThrashGuard’s 60-second case and tier-2 exclusion (`ThrashGuard.cpp:59–74,139–145`); both in dispatch; both in `stateNames[7]` and `stateShortName()` (`Generalized-Core-Counter.cpp:140–176`); both in the diagnostic name switch (`ConnectivityFailsafeTest.cpp:25–42`); and an `isSleepState()` guard for retained span closure (`Generalized-Core-Counter.cpp:1454–1475`). Adding an enum in the middle also renumbers later states recorded in retained forensics (`LoopForensics.cpp:154–177`) and boot logs.

**Inference:** a visible top-level split is not behavior-neutral. Masking both names/numbers as legacy “Sleep” still creates a NAP↔NIGHT transition at a boundary, changing `publishStateTransition()` and ThrashGuard progress (`Generalized-Core-Counter.cpp:1445–1451`). Avoiding that transition reduces the design to one state selecting phase scripts. The equivalence transcript would have to freeze, pass by pass: API calls, `state/oldState`, exact `State:`/`StateReq:`/`LoopStage:` lines, retained state number, breadcrumbs, alerts, watchdog order, timings and transitions for openness × mode × gate × modem × sleep result × wake source. Any Nap/Night name or extra transition fails it.

**Recommendation:** keep one top-level state and use six phase modules. It reaches the thin-script goal without compatibility masking, enum churn, or changed forensic output.

Future-WO note only: NIGHT teardown may later block, but today both waits service the awake watchdog and Device OS (`State_Sleep.cpp:715–724,835–842`). A blocking version must either service or deliberately pause/restore both watchdog regimes. Timing must still start at the request and end at actual completion, preserving `ModemHealth`’s >10,000 ms unstable threshold and ≤5,000 ms recovery threshold (`ModemHealth.h:4`, `ModemHealth.cpp:34–52`). No behavior change belongs in this split.
