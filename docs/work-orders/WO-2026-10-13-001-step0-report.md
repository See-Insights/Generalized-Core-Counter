## Q2: history of `sensorISR` and the PIR ISR count

- **OBS, `sensorISR` was never attached.** `git log -S'sensorISR' -- src` returns only `8f889ae` (2025-12-26, initial import). `git log --all -G'attachInterrupt\([^)]*sensorISR'` returns nothing. At `8f889ae` the only `attachInterrupt` calls were `userSwitchISR` and the PIR's `pirISR`. The declaration comment reads "Interrupt for legacy tire-counting sensor" (`Generalized-Core-Counter.cpp:116`).
- **OBS, the evidence doc says the same:** `2026-10-07-step6-extensibility-evidence.md:89`: "`sensorISR` … legacy tire counter … is declared and defined but never attached; `sensorDetect` is therefore never set true". `:129`: "Dead legacy divergence: `sensorISR` keyed on sensor type … (never attached)". `WO-2026-10-08-002-sensor-type.md:25`: "Leave `sensorISR` … for WO 2a."
- **OBS, `_isrCount` has no reader.** It came in with `8f889ae` and has no getter in `src/`. The code comment says it exists "so we can see in the main loop whether the ISR is ever firing" (`PIRSensor.cpp:5–6`), but nothing reads it. The live interrupt path is `pirISR` + `_motionDetected`, which stay.
- **OBS, no entry names these as the seed of an interrupt reading mode.** I searched `CHANGELOG.md` and `docs/work-orders` for `sensorISR`, `isrCount`, "interrupt-driven" and "interrupt mode". The only interrupt-mode artifact is `SamplingMode` INTERRUPT=0/POLLING=1 (`CHANGELOG.md:472`; `MyPersistentData.h:149`, default `MyPersistentData.cpp:147`). The evidence doc `:131` says it is "persisted, ledger-applied … but read by no behavior".
- **INF verdict:** neither is a seed. `sensorISR` is tire-pressure-specific (`frontTireFlag`, sensor type 1); the interrupt mode the design needs is `samplingMode` + `ISensor::usesInterrupt()` (`SensorManager.cpp:324`) + `pirISR`, none of which are touched. Delete both; none is "keep for 2b".
- **OBS, side effect to note:** `sensorISR` is the last reader of `SystemConfig::get_sensorType()` (legacy `sysStatus.sensorType`, `Generalized-Core-Counter.cpp:2711`). `sensorDetect` (`:157`, read at `State_Sleep.cpp:1094`, `State_Idle.cpp:255`) is then never written. Both stay in 2a, since removing them touches live branches or persisted-field accessors. See Open points.
