## Plain goal

Move from Device OS 6.4.1 (`project.properties:3`) to 6.6.0 to pick up its fixes, including the sleep-configuration leak we reported on 2 Oct, as **one variable**: v44 = v43's application code built for 6.6.0, nothing else. This Step 0 finds what in our code the 6.5.0/6.6.0 changes touch, so the soak knows what to watch.

## Step 0 questions (report ≤ 100 lines on the WO branch)

Every claim about a release-note item cites the note; every code claim cites file:line on main (§13 (j)).

1. **The leak.** 6.6.0 fixes the `SystemSleepConfiguration` move-assignment leak **we reported** (`WO-2026-10-02-003-particle-bug-report-draft.md`; about 117–141 B per sleep, ~22 KB in 3 h). WO-2026-10-02-003 worked around it by building each configuration as a fresh local (`State_Sleep.cpp:1135,1364,1464,1481`, `Generalized-Core-Counter.cpp:879`). Confirm the fix is the one we reported, that the workaround stays harmless on 6.6.0 (keep it; no change), and say what `fh` should do on the bench (expected: no change, since we no longer hit it). Mark the draft bug report as resolved upstream. List any other heap/thread fixes (6.5.0: `tcp_pcb` double-free, terminated-thread resources) that our paths hit.
2. **Behavior changes that touch our code:**
   - `Cellular.disconnect()` now disconnects the cloud first. `Connectivity::requestRadioPowerOff()` (`power/Connectivity.h:25–28`) calls it **without** `Particle.disconnect()`; list every caller and say what changes in the sleep teardown, the modem-off budget (alert 15) and the standby latch.
   - The non-blocking cloud handshake and the cloud dropping and resuming with its interface: the effect on `connecttime`, the connect state machine's timeouts and `ConnSummary` timing.
   - The 6.5.0 keepalive changes (default values, per-interface keepalive): what our KEEP_ALIVE mode sets and whether the effective value changes.
   - The ledger fix (HardFault on cloud disconnect during a ledger update) and the new result/error responses: any code that parses ledger results.
   - Cellular: unresponsive-AT recovery, `disconnect()` state reset and registration backoff. Could these change the Dev-14-style stuck registration (recovery plan, 15 Oct)?
   - The 6.5.0 AM18x5 `POWER_OFF` race fix and the 6.4.0 built-in AM18x5 driver: any conflict with our own `AB1805` library (`Generalized-Core-Counter.cpp:133`) on the same I2C device.
3. **Inbound-sync API.** Is the inbound ledger-sync notification (Particle forum, 13 Oct) in 6.6.0? If so, note it; don't adopt it here.
4. **Build and size.** Install the 6.6.0 toolchain; build v43's code for 6.6.0 with a fresh `BUILD_PATH_BASE`; report text/data/bss and `.bin` size against v43 on 6.4.1 (152494 B), and any warnings that are new. Suite `N/N`.
5. **OTA and rollback.** What the fleet downloads (system parts, bootloader, softdevice, NCP?) and the approximate bytes per device; whether a device on 6.6.0 can still run a 6.4.1-built app (the rollback path), and what Particle's product-firmware page requires for the OS change.
6. **Docs to change:** `project.properties`, README, `AI_DEVELOPMENT_WORKFLOW.md` toolchain paths. List them; don't edit yet.
