## The plain goal
Every occupancy change, start or end, is reported right away unless the mode in use is INTERMITTENT. In INTERMITTENT, changes wait for the scheduled report, as today.

**Short answer.**
- **Root cause (OBS and INF):** the soak end was found by the main-loop handler while `state == SLEEPING_STATE`. That handler latches the flag but cannot transition (`State_Modes.cpp:155`).
- **Why the wake path missed it (INF):** the sleep-wake end check never fired because its LED gate was false. The LED had already been turned off by earlier untrusted-clock close attempts.
- **Recommendation:** (B), plus one shared predicate. Estimate +18, so PROCEED. It has a hard dependency on `State_Report.cpp:275` and two architect questions (sections 5 and 7).

**Sketch.** The five `reportNow` sites call one predicate. A flag latched in any non-Idle state is read at the first quiet point, Idle or sleep prep, and sent to REPORTING. Report already clears it and connects (`:216-222`) when offline.

**Interaction with the latch at `State_Report.cpp:275`.**
- With consumers that do not clear the flag, the `already connected` branch leaves it set, so Idle → REPORTING → Idle repeats every loop (a livelock).
- That line is out of scope, but (B) turns the stale latch from harmless into a livelock. The one-line clear is therefore a prerequisite, either folded in (+1, in the +18) or landed first.
- If the architect refuses it, the consumers must clear the flag themselves. Then Report skips its flag branch, so a mode-3 report loses the modem-unstable bypass (`:233`) and a duplicate report fires per connected event.

## 5. DISCONNECTED (mode 2): architect decision
- "Unless INTERMITTENT" includes mode 2 literally.
- The code does not keep mode 2 offline in Report or Connect. There is no `DISCONNECTED` test there (grep). The only users are `Generalized-Core-Counter.cpp:2567` (failsafe skip) and `State_Sleep.cpp:46` (label).
- `docs/architecture-overview.md:301` says mode 2 "suppresses automatic connection attempts". The code does not match that.
- With the flag set, an immediate report in mode 2 would connect. A mode-2 device with no connection would wake the modem on every change.
- Options: include mode 2 (connects), or make the predicate `mode ∉ {INTERMITTENT, DISCONNECTED}`. One line changes either way. Not decided here.

## Open points
- **`:275`:** fold in the one-line clear or land it first. Without it, (B) livelocks.
- **Mode 2:** include it or exclude it (section 5).
- **Redundant report:** a flag latched after a Report already ran gives one redundant report. A stale flag from before the `:275` fix does the same once.
- **`lastReport`:** `Report:82` stamps `lastReport` on every immediate report. In mode 0, each change resets the Idle schedule check (`Idle:181`). Mode 3 already behaves this way.
- **Wake log:** `State_Sleep.cpp:76` always prints `led=0s` (unit bug, `/1000UL` on seconds). Out of scope.
- **Mode 1 timer wakes:** while occupied, each timer wake runs `sleep-timer-report` (`Sleep:1762`) with no suppress. This is existing mode-1 behaviour; the goal keeps it.
