## 2. Findings for the architect (none blocks PROCEED)

1. **The phase T0 carries the connect delay.** `timestamp` is the time `publishData` ran (`nowStampSec`; `stampOverride` is always 0 at every call site, `ReportPublisher.cpp:102`), which for a session-start report is **after the connect completes** (hook `connecttime` of 2 to 150 s on Dev-14 today). So T0 is late by up to minutes, **which shifts expected closes later and can move credit between report windows**; the per-day total is unaffected except in the last session before the close hour. The script keeps the WO's rule and adds `--phase-offset-s` (default 0, applied to T0) so the offset can be tried; the output states the uncertainty. Per-window errors of a few minutes may be this, not firmware.
2. **The WO says each pulse is held 2 s high; the V1 exerciser firmware holds 200 ms** (`Exerciser-Board/src/main.cpp`, `PULSE_HIGH_MS 200`; the handover says 200 ms). The expected-credit arithmetic uses pulse start times only, so nothing changes; the pulse width is not a script parameter.
3. **Occupancy-change reports exist only in INTERMITTENT_KEEP_ALIVE and CONNECTED** (`reportsOccupancyChangesNow()`); Dev-14's hooks every 5 min today show that. In other modes there is no session-start report and the phase has no source: the script exits with "no occupancy=1 report" for that day rather than guessing.

## 3. Script design and size

`tools/exerciser_baseline.py`, Python 3 standard library only, no network: parse args (`--hooks DIR --status DIR --id --dates --tz --open --close --debounce-ms --cycle-s 1200 --pulses 10 --spacing-s 30 --phase-offset-s 0 --exclude START..END --csv FILE`); load hooks (sorted by `timestamp`, local day by `--tz`); per day T0, sessions `k=0…` with expected close `T0 + k·cycle + (pulses−1)·spacing + debounce` counted if before the local close hour (**strict `<`**); expected credit per session `(pulses−1)·spacing + debounce`; per day: measured = last `dailyoccupancy` of the day, expected, error (min and %), session count, flags (missing reports = gaps over 1.5× the median spacing, resets from status files, excluded windows); per window: measured diff, expected sum of sessions whose expected close falls in `(prev, ts]`, error, with the "±1 min is truncation" note; summary per `fw_version`: mean and standard deviation of the daily error and of the window error, with counts; CSV. About **170 lines**.
