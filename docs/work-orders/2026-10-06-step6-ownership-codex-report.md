**2. Data flow**

1. **Battery acquisition/acceptance:** SensorManager reads raw/normalized SOC and voltage, retries suspicious samples, then substitutes a linear voltage estimate or previous SOC; later samples can lose to the pre-radio acceptance fence. **Two judgments:** sample acceptance here versus subsequent Health trust (`SensorManager.cpp:519–612,628–677`).

2. **Trust:** SensorManager passes accepted SOC, current voltage, post-remediation charge state and later radio state to BatteryHealth. Thus inputs need not describe one simultaneous measurement. The resting curve is explicitly unvalidated; charging widens the negative residual allowance, radio load the positive side (`SensorManager.cpp:735–743,827–834`; `BatteryHealth.cpp:14–32,94–102`). This confirms the code concerns in the October 4 report, not its historical fleet rates (`docs/work-orders/2026-10-04-pre-step6-known-issues-codex-report.md:71–96`).

3. **Tier:** Authority → BatteryTierGuard → BatteryBackoff, with PowerTier supplying the voltage floor: Suspect **and** Untrusted substitute OCV SOC; ≤3.5 V or invalid voltage forces SURVIVAL. These are stages of one pipeline, not independent production authorities (`BatteryTierGuard.cpp:5–17`; `PowerTier.h:37`; `BatteryAuthority.cpp:32–57`). **Correction:** HEALTHY falls to CONSERVING below 70%; 75% restores HEALTHY (`cloud/BatteryBackoffPolicy.h:20–28`).

4. **Multiplier:** ReportingPolicy uses tier multipliers 1/2/4/12, multiplies configured interval and resolves connection boundaries. Local report generation precedes the connection decision (`RuntimeReportingPolicy.cpp:43–53`; `BatteryBackoffPolicy.h:45–56`; `ReportingPolicy.cpp:63–88`; `State_Report.cpp:67–69,244`).

5. **Connection mode:** ConfigApply and Authority compete over the persisted setting; downgrade applies only to OCCUPANCY KEEP_ALIVE at CONSERVING or worse. Report/Sleep/Modes consume that overwritten setting (`ConfigApply.cpp:445–455`; `BatteryAuthorityCommand.cpp:76–100`; `State_Report.cpp:231`; `State_Modes.cpp:79`; `State_Sleep.cpp:1719`).

6. **Failsafe:** usually reads **persisted tier**, evaluating only if that value is invalid; external-power classification uses PowerPlatform’s raw/fallback source, not PowerManager’s correction. It suppresses hard action on battery when sticky downgrade or SURVIVAL applies; it does not subtract deliberate connection spacing (`Main:355–382,2612–2620,2655–2671`). **Verified citation correction:** the block is `2655–2671`, not the supplied `2641–2656`.

7. **Publication:** reports contain accepted `battery`, cached `vc` (0 when unavailable), state label and persisted `temp`; status contains cached voltage (−1 sentinel), charge label, **freshly evaluated tier**, persisted downgrade and cached trust (`Main:1991–2021,2034–2040`; `DeviceStatusPublisher.cpp:196–206,245–257`). ChargeDiag uses raw source; PowerDiag/status use effective source. HOST/ADAPTER both select USB profile, so swapping alone does not establish a profile change or its physical cause (`PmicFaultMonitor.cpp:400–414`; `PowerDiagnostics.cpp:233–235`; `DeviceStatusPublisher.cpp:240–243`; `PowerManager.cpp:33–37`).

8. **Temperature:** TMP112 wins when detected/forced; otherwise Boron samples TMP36 on A4 eight times. The same call feeds thermal policy and persisted report temperature; invalid readings can publish fallback temperature, but cannot release an existing inhibit (`SensorManager.cpp:983–1011,1035–1094,1173–1202`; `device_pinout.cpp:34–39`; `ChargeInhibitPolicy.h:168–177`; `Main:2021`). **O:** source establishes conditional selection; physical sensor presence cannot be established here.

9. **Occupancy:** PIR ISR → 500 ms event debounce → SensorManager loop → Modes; PIR wake also enters through Sleep. Idle and Modes independently test session expiry, using `>=` versus `>`, before the common close/credit helper; reports publish persisted occupancy/totals (`PIRSensor.cpp:11–13`; `PIRSensor.h:76–86`; `State_Modes.cpp:61,141`; `State_Idle.cpp:57–60`; `State_Sleep.cpp:1695–1711`; `State_Common.h:374–402`; `Main:2011–2017`).
