## 1. The mechanism, cited

- **Close cleanup:** `handleReportingState()` takes `DailyBoundary::check(now)` (`State_Report.cpp:40`). When due and occupied it closes the session **through the boundary**: `closeOccupancySessionSafely("daily-cleanup", boundary)` (`:58-60`). It publishes with stamp `boundary - 1` (`:70`), then `dailyCleanup()` (`:78`), whose `PIRSensor::resetTotals(Daily)` zeroes `occupied`, `lastOccupancyEvent`, `occupancyStartTime` and `totalOccupiedSeconds` (`PIRSensor.cpp:14-23`; `State_Report.cpp:306-326`). Only `close == 24` keeps a session open across it: `occupied` is set true again with start `max(boundary, originalStart)` (`:79-82`).
- **Awake detection:** `handleOccupancyMode()` (`State_Modes.cpp:63`) calls `SensorManager::instance().loop()` (`:65`). On a detection with `occupied` false it sets `occupied` and `occupancyStartTime = Time.now()` (`:67-71`); with `occupied` true it only restarts the LED and debounce (`:95-106`). `updateOccupancyState()` then closes on debounce expiry through `closeOccupancySessionSafely("modes")` (`:147`). `State_Idle.cpp:61` closes the same way (`"idle"`).
- **Wake detection:** `processSleepWakeEvent(pirWake)` (`State_Modes.cpp:165`, called at `State_Sleep.cpp:1053`) opens a session in its OCCUPANCY branch (`:206-270`) with the same fields, and closes an expired LED window via `"sleep"` (`:171`).
- **Credit:** `closeOccupancySessionSafely()` adds `closeAt - effectiveStart` to `totalOccupiedSeconds` (`State_Common.h:333-395`); `closeAt` defaults to `Time.now()`.
- **Why it lands in the next day (observation, from the code):** after the cleanup zeroes the total, a device still awake before night sleep gets a PIR hit, opens a session (nothing checks openness), and its debounce close adds minutes to the zeroed total. The morning wake does not zero it again, so the first report of the day carries them (the +5 to +7 on Dev-14 and Dev-09).
- **0-24:** `isWithinOpenHoursForHour` is `hour >= open && hour < close` (`Clock.cpp:14-18`), so for 0-24 `Clock::openness()` is never `Closed`. `openness()` returns `Unknown` for an untrusted clock or an invalid config (`Clock.cpp:567-577`).

## 2. The single gate

A helper in `State_Common.h`, next to `reportsOccupancyChangesNow()`:
`inline bool occupancyIgnoredWhenClosed() { return Clock::openness() == Clock::Openness::Closed; }`
Used at the two points where a session is **started or extended**:
1. `handleOccupancyMode()`: `if (SensorManager::instance().loop() && !occupancyIgnoredWhenClosed())`. `loop()` is still called so the sensor's flag and debounce are consumed.
2. `processSleepWakeEvent()`: wrap the `OCCUPANCY` branch (`:206-270`) in the same test, with a log line.

Because it keys on `== Closed`, 0-24 sites and `Unknown` (untrusted clock, item 19's territory) behave exactly as today, and COUNTING is untouched (its branches are separate: `State_Modes.cpp:29` and `:191`).

## 3. Edge cases

- **Session open at the close:** the cleanup closes it through the boundary (`:60`), so it is credited up to the close. **Gap found:** if the debounce expires **after** the boundary but **before** the close report is processed, `updateOccupancyState()` or the idle path closes with `closeAt = Time.now()` and credits minutes past the close into today's total, then the cleanup zeroes it (fine for the next day, but today's close report is then slightly high). Fix inside the same helper area: when `Closed` on a normal-hours site, clamp `closeAt` to the last boundary (about +3 lines). Needs the architect's say (§4 Q2).
- **Reset between the close and night sleep:** `occupied` and `occupancyStartTime` are retained, but the clock may be `Unknown` after boot, so the gate lets a detection through until trust returns. That is today's behavior and belongs to item 19, not this WO.
- **COUNTING:** unaffected. **Closing report `occupancy` field:** the report reads `get_occupied()` after the cleanup (`PIRSensor.cpp:25-28`), so it reads 0 and the next day starts at 0 with the gate on.
- **Tests that must move:** the S-6 wake harness cases that detect after the close and expect a session.
